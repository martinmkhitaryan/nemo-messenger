# Nemo v1.1 (nice-to-have)

v1 product code is in this tree. This file is the follow-on list. It is **not** a specification: `README.md`, `docs/decisions/`, and `docs/protocol/` win if they disagree.

Next free ADR is **0036**. Do not add a push table, P2P ICE, JSON protocol objects, or libsignal on the server without a record.

Manual live-call check (you): [`testing.md`](testing.md).

---

## Pull these forward for v1.1

Wire hooks already exist. Do not ship a mode or API that lies.

| ID | Item | Notes |
| --- | --- | --- |
| N1 | Tor / Arti | Privacy `High` has a hop flag. Plug Arti behind `EnvelopeSink`. No system `tor` binary ([ADR-0028](decisions/0028-implementation-languages-and-libraries.md)). Calls stay unavailable on Tor ([ADR-0024](decisions/0024-voice-call-architecture.md)). |
| N2 | Cover traffic / Maximum / constant-rate | Dummy envelopes are wire-compatible. Client-generated only ([ADR-0021](decisions/0021-privacy-layer-and-modes.md)). Do not enable `High`/`Maximum` in the UI until the traffic is real. |
| N3 | Group calls | SFrame (RFC 9605) from a call-specific MLS group, plus a blind SFU ([ADR-0024](decisions/0024-voice-call-architecture.md)). Video stays out unless a new ADR says otherwise. |
| N4 | FCM HTTP v1 | Opaque wake token only ([ADR-0020](decisions/0020-opaque-push-wakeup.md)). Needs **ADR-0036** for any push-endpoint table (DDL is frozen, [ADR-0033](decisions/0033-local-http-api-and-postgres-schema.md)). Operator service account; not a protocol object. |

## Out of v1 (README §52)

Not leftover v1 work. Same as today unless a later ADR pulls one in.

| Item | What it is | Effort |
| --- | --- | --- |
| iOS / macOS | New Apple shell (SwiftUI) on the same `nemo-core` / UniFFI. PushKit/CallKit, Apple TLS, App Store, no JNA. | Large. Months. New ADR for APNs. Rust core mostly reusable. |
| Web | Browser client. WASM or a gateway would see keys or ciphertext in a place ADR-0026 forbade. | Very large, and a product decision first. Do not start without an ADR that supersedes “no web in v1”. |
| Multi-device | Two phones as one person. ADR-0003 is one installation = one identity. Linking needs a key hierarchy or a pairing protocol. | Very large. New ADR that supersedes 0003 (or an honest “two identities” UX). Touches ratchet, MLS, vault, discovery. |
| Key transparency | Public log that a home cannot silently swap a contact’s key. | Large. New service, gossip, and client audits. Independent of v1 messaging. |
| OS keystore wrap | Android Keystore / DPAPI / libsecret wrap the SQLCipher key so unlock can be biometric. Deferred in ADR-0034. | Medium. Three platform paths. Vault format can stay; wrap the raw key. |
| P2P ICE | Direct media, skip TURN. ADR-0024 forbids it (peer would learn your IP). | Small in WebRTC, large in privacy. Needs a new ADR. Easy to ship wrong. |
| Backup / history export | Dump or restore messages, chats, or keys. | **Do not implement.** [ADR-0023](decisions/0023-no-backup-no-recovery.md) forbids it. Not a v1.1 item. |

## Already decided (do not re-open)

No identity recovery, no cryptographic-state export, no history backup or export ([ADR-0023](decisions/0023-no-backup-no-recovery.md)). The vault is at-rest encryption on that device, not a backup.
